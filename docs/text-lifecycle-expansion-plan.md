# Text Composition and Editing Lifecycle Expansion

Accepted scope: all major text forms, full original drafts and substantial rewrites, and representative live tests alongside complete static and manual review.

## Deliverables

- Add `text-composition` (nine modes), `text-revision` (seven modes), `text-translation` (three modes), and `textual-scholarship` (four modes).
- Add five `publishing-editorial` modes: proofreading, publication format review, indexing, general submission packages, and edition maintenance. Deepen all eight existing editorial modes and their supporting artifacts.
- Add 22 agents: eight composition roles, four revision roles, two translation roles, four textual-scholarship roles, and four publishing roles. Reuse `developmental-manuscript-editor` for structural revision and `indexing-coordinator` for indexing.
- Preserve existing names and mode identifiers. Update lifecycle routing, overlaps, skill coverage, model counts, and README inventory. Expected totals: 133 agents, 26 gateways, 104 workflows.

## Behavior

Composition covers briefs, ideation, source synthesis, outlines, fiction, nonfiction, essays, poetry, dramatic texts, professional prose, and scholarly manuscripts. Revision covers applied structural changes, feedback reconciliation, rhetoric, continuity, reader orientation, and adaptation. Translation covers planning, complete translations, and comparative review. Textual scholarship covers witnesses, transcription, normalization policy, variants, and critical editions. Production continues through proofs, accessible formats, verified indexes, submission preparation, and later corrections or editions.

Every mode needs discriminating intake, domain decisions, concrete verification, a stable output contract, a substantive working artifact, a worked example, and a failure case. Gateways load only relevant workflows. Actual drafts and revisions must be delivered when requested; examples or reports must not substitute for them. Preserve deliberate voice and experimental form, source evidence, concurrent edits, and explicit coverage limits for long manuscripts.

Use Terra/high for composition and revision, Sol/high for translation, collation, and critical editions, Luna/medium for routine proofreading, and Terra/medium for packaging and maintenance. Dedicated reviewers and witness analysis remain read-only; artifact creation uses workspace-write. Support existing text and document formats through available tools without adding a conversion application or performing unauthorized publication.

## Acceptance

- Inspect and score every new or modified agent and every affected gateway mode against the catalog rubric; all required criteria must score at least 3.
- Validate TOML/YAML, names, fields, references, handoffs, reachability, output alignment, registry totals, progressive disclosure, and `git diff --check`.
- Verify discovery and configuration loading with current stable Codex; record the actual version and model settings.
- Live-test all seven drafting forms and representative handoffs: brief/draft/revision, conflicting feedback, voice/continuity, adaptation, translation/review, witness/transcription/collation/edition, proof/package, and edition correction.
- Retain inputs, outputs, observed failures, corrective reruns, and clear static/manual/live verification boundaries. Do not claim untested behavior as verified.
