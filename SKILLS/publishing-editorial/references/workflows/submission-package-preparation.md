# Submission Package Preparation

## Purpose

Prepare complete literary, book, essay, or other general submission materials against supplied destination requirements without submitting them.

## Intake

Capture destination and requirements/version, work type and stage, author facts, manuscript extent, requested components, deadline, anonymity rules, prior submissions, and permitted file changes.

## Workflow

1. Extract the destination’s actual requirements: eligibility, genre, length, format, anonymity, attachments, synopsis/sample, biography, disclosure, and submission method. Separate supplied requirements from assumptions.
2. Map each requirement to a component, owner, source evidence, and status. Reuse verified metadata and manuscript facts across materials.
3. Draft the requested cover/query letter, synopsis, proposal elements, biography, or statement in full. Keep a synopsis faithful to the actual work and distinguish it from promotional copy.
4. Assemble or identify the intended file set with consistent versions and names; check that anonymized and identified components are separated as required.
5. Return completed materials, package checks, and concrete gaps. A preparation task ends with a reviewable package, not a claim of submission.

Read [submission-package-preparation-kit.md](../artifacts/submission-package-preparation-kit.md) when preparing the working record or checking the example against a similar request.

## Decision Rules

- Do not invent credentials, awards, endorsements, publication history, or requested disclosures.
- Preserve the relationships actually stated in author facts. Living in a city and having an occupation does not establish that the person performs that work in that city; connective wording must not invent that relationship.
- A destination requirement must come from the supplied or actually retrieved instructions; do not assume one publisher’s rules apply elsewhere.
- Missing metadata permits a draft with a precise query; it does not require abandoning all package preparation.
- Changing a work’s ending in a synopsis misrepresents the manuscript even if it makes a stronger pitch.

## Verification

- Cross-check title, author, extent, genre, synopsis facts, and contact fields across materials.
- Check filenames, required components, anonymity, and word/page limits against the actual instructions.
- Distinguish locally assembled files from uploaded or submitted ones.

## Output Contract

Return exactly: `Submission Materials`, `Requirements Matrix`, `Package Inventory`, `Consistency Checks`, `Open Items`, `Files Changed`, `Handoffs`.
Include supplied source or manuscript locations where relevant; distinguish applied changes, recommendations, unverified details, and coverage still outstanding. Put the requested text in the text section or identify the actual output file.

## Handoffs

Use `journal-submission-specialist` for scholarly journal requirements, `book-metadata-packaging-editor` for positioning copy, `permissions-reviewer` for supplied rights questions, and `production-editor` for package sequencing.

## Boundaries

Do not send, upload, pay, or submit without explicit action authority. Do not imply publisher acceptance or missing coauthor/owner approvals.
